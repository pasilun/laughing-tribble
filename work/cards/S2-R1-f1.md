Defect (checkpoint S2-R1, reviewer): a malformed id makes the storage layer throw (`lib/plan/storage/docs.ts:32`). `get`, `edit` and `list` with `what: revisions` then return JSON-RPC error -32603 instead of `ok: false` with `isError`. Seen live with id `"Bad Id!"`.

Do: in each of the three handlers, check the id shape before calling the store. An id that does not match the store's rule (read the rule in `lib/plan/storage/docs.ts` near line 32, and use the same regex) is `badArgument('id', 'ogiltigt id')`. Also wrap the store call in try/catch: a thrown error becomes `invalidOperation(message)` for `edit`, and `notFound(id)` for `get` and `list` revisions. Nothing else changes.

Test (`e2e/connector-errors.spec.ts`, new, API): `get { id: 'Bad Id!' }`, `edit { id: 'Bad Id!', base_revision: 1, ops: [] }`, `list { what: 'revisions', id: 'Bad Id!' }` each give `structuredContent.ok === false`, `isError === true`, and a JSON-RPC result (no `error` in the body).
