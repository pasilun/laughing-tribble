`lib/plan/connector/types.ts`:
```ts
export const CONTRACT = 1 as const
export const TOOL_NAMES = ['guide', 'list', 'get', 'check', 'view', 'scan', 'edit', 'source', 'manage', 'export'] as const
export type ToolName = (typeof TOOL_NAMES)[number]
export type Level = 'error' | 'warning' | 'info'

// Contract §5. `id` is stable for the same cause; `code` is stable for ever.
export type Finding = {
  id: string
  code: string
  level: Level
  message: string
  refs?: string[]
  fix?: Array<Record<string, unknown>>   // operations for `edit` that mend it
  data?: Record<string, unknown>
}
// Contract §6: a call ready to make.
export type Next = { tool: ToolName; arguments: Record<string, unknown>; why: string }
export type Changed = { kind: string; id: string; what: string }
// Contract §4. Keys that do not apply are left out.
export type Answer = {
  ok: boolean
  contract: typeof CONTRACT
  engine: string
  id?: string
  revision?: number
  changed?: Changed[]
  findings?: Finding[]
  next?: Next[]
  data?: Record<string, unknown>
}
```

`lib/plan/connector/answer.ts`:
```ts
import { CONTRACT, type Answer, type Finding } from './types'

// A short id of the running version, for bug reports: the commit on Vercel, 'dev' elsewhere.
export function engineVersion(): string {
  const sha = process.env.VERCEL_GIT_COMMIT_SHA
  return sha ? sha.slice(0, 7) : 'dev'
}

// A finding. Without an id, the id is the code, plus the refs joined with '+' when there are any.
export function finding(f: Omit<Finding, 'id'> & { id?: string }): Finding {
  const id = f.id ?? (f.refs && f.refs.length ? `${f.code}:${f.refs.join('+')}` : f.code)
  return { ...f, id }
}

// An answer. `contract` and `engine` are filled in. The keys come out in this order:
// ok, contract, engine, id, revision, changed, findings, next, data. A key with no value is left out, and so is an
// empty list or an empty `data` object.
export function answer(parts: Omit<Answer, 'contract' | 'engine'>): Answer
```
Pseudo-code for `answer`: start with `{ ok: parts.ok, contract: CONTRACT, engine: engineVersion() }`; then for each of `id, revision, changed, findings, next, data` in that order: skip when `undefined`; skip when it is an array of length 0; skip when it is `data` with no keys; otherwise copy it. `revision: 0` is kept (a number is a value).

Tests (`e2e/connector-answer.spec.ts`, pure, `import { test, expect } from '@playwright/test'`, import with the `@/` alias):
- `answer({ ok: true, id: 'p1', revision: 3 })` equals `{ ok: true, contract: 1, engine: expect.any(String), id: 'p1', revision: 3 }` and `Object.keys` is `['ok', 'contract', 'engine', 'id', 'revision']`.
- `answer({ ok: true, findings: [], changed: [], next: [], data: {} })` has the keys `['ok', 'contract', 'engine']` only.
- keys are in the order of the comment above when all are given.
- `engineVersion()` is `'dev'` when `VERCEL_GIT_COMMIT_SHA` is unset, and `'abcdef1'` when it is `'abcdef123456'` (set `process.env` inside the test and restore it after).
- `finding({ code: 'X1', level: 'error', message: 'm' }).id === 'X1'`; with `refs: ['a', 'b']` the id is `'X1:a+b'`; with an explicit `id: 'custom'` it stays `'custom'`.
