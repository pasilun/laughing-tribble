Do: a reader of doorways in archive drawings, as they are drawn in the 1999 survey of lgh 152–154 (`e2e/fixtures/flat/a00-crop.png`, placed by `case.json`). Today's reader (`newOpenings` in `lib/plan/scan/openings.ts`), given the fixture's own walls, finds **7 of the 23 doorways and proposes 16 that are not there**; it finds all 7 windows. This card is a design task: there is no ready code. Read the drawing, find the rules, write the reader, and make the test pass.

**The goal (the test below):** given the fixture's walls with its openings removed, find at least **15 of 23 doorways with at most 6 extra**, and keep **7 of 7 windows with at most 2 extra**.

**How the survey draws a doorway** (from building the fixture with the maintainer; also `guide` topic "trace", registry `CONVENTIONS` in `lib/plan/connector/registries/index.ts`):
1. `doorway-cross-bars`: in a solid or outlined wall, a hollow stretch (the wall's core is white, both face lines continue) between two short bars across the wall. Most doorways here: the closets east in 153 (`iv-153-klk-v`), the stair-side hall doors (`lg-trapphus-153-154`), the WC cells, the hall of 154.
2. `doorway-dashed`: the wall continues as a dashed line across the opening (kitchen–dining in 154 `iv-154-garderob-s` and in 153 `iv-153-kok-n`; the stair entrance of 152 in `bv-norr`).
3. `doorway-ticks`: in a double-line wall, both lines break, with a short tick at each end (the south room of 154 in `iv-154-wc-s`).
Not doorways: a junction where another wall meets (the face lines break there too), fixtures drawn against a wall (counters, cupboards, bathtubs), text and its underline. Door swings are not drawn and not wanted: openings have `kind: "opening"` and no hinge or swing. Windows: keep what `newOpenings` does for them (all 7 found today).

**What to write**
1. New file `lib/plan/scan/doorways.ts` with `export function readOpenings(g: Gray, r: Raster, plan: Plan): Opening[]`: every opening it finds on the plan's walls (`id` unique, `wallId`, `kind` `"opening"` or `"window"`, `offset` and `width` in mm along the wall from `a`, `phase: "existing"`). 2. New test `e2e/scan-openings-1999.spec.ts`, exactly this (do not lower `LIMITS`):
```ts
import { test, expect } from '@playwright/test'
import { readFileSync, writeFileSync, mkdirSync } from 'fs'
import sharp from 'sharp'
import { scorePlan } from '@/lib/plan/bench/score'
import { readOpenings } from '@/lib/plan/scan/doorways'
import type { Plan } from '@/lib/plan/domain/types'

// T-07: openings read from the 1999 survey with the fixture's walls given (only the openings are taken away), scored
// against the fixture's openings. Doorways count by centre within 300 mm on the right wall; windows the same. The
// limits are the target of card T-07; raise them when the reader improves, never lower them.

const F = 'e2e/fixtures/flat'
const LIMITS = { doorways: 15, windows: 7, extraDoorways: 6, extraWindows: 2 }

test('openings read from the 1999 survey match the fixture', async () => {
  test.setTimeout(120_000)
  const ref = JSON.parse(readFileSync(`${F}/drawing-1999.json`, 'utf8')) as Plan
  const c = JSON.parse(readFileSync(`${F}/case.json`, 'utf8')) as { mm_per_px: number; x: number; y: number }
  const { data, info } = await sharp(readFileSync(`${F}/a00-crop.png`)).grayscale().raw().toBuffer({ resolveWithObject: true })
  const g = { data: new Uint8Array(data.buffer, data.byteOffset, data.byteLength), w: info.width, h: info.height }
  const r = { id: 'a00', mmPerPx: c.mm_per_px, x: c.x, y: c.y, widthPx: info.width, heightPx: info.height, src: '', rotation: 0 }
  const bare = { ...ref, openings: [] }
  const found = readOpenings(g, r, bare)
  const score = scorePlan(ref, { ...bare, openings: found }).openings
  mkdirSync('test-results', { recursive: true })
  writeFileSync('test-results/openings-1999.json', JSON.stringify({ score, found }, null, 1))
  console.log('OPENINGS', JSON.stringify(score))
  expect(score.doorways.found).toBeGreaterThanOrEqual(LIMITS.doorways)
  expect(score.windows.found).toBeGreaterThanOrEqual(LIMITS.windows)
  expect(score.doorways.extra).toBeLessThanOrEqual(LIMITS.extraDoorways)
  expect(score.windows.extra).toBeLessThanOrEqual(LIMITS.extraWindows)
  // Every opening is on a wall of the plan and inside it.
  for (const o of found) {
    const w = bare.walls.find((x) => x.id === o.wallId)!
    expect(w, o.id).toBeTruthy()
    expect(o.offset).toBeGreaterThanOrEqual(0)
    expect(o.offset + o.width).toBeLessThanOrEqual(Math.hypot(w.b.x - w.a.x, w.b.y - w.a.y) + 1)
  }
})
```
   It writes what was found to `test-results/openings-1999.json`; compare with `openings` in `e2e/fixtures/flat/drawing-1999.json` to see what is missed and what is extra. Do not read the fixture's openings inside `readOpenings` (the test removes them; the reader must work on drawings that have no fixture).
