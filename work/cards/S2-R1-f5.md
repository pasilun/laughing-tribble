Defect (checkpoint S2-R1, reviewer): topic content is written as literals in the `guide` handler (`guide.ts:241-252`), and list kinds as literals in `list.ts` (around lines 322, 326). A topic added to `TOPICS` falls silently to the `WORK` text.

Do: do not change `names.ts`. In `registries/index.ts`, add an exported map `TOPIC_TEXT: Record<string, string>` with a key for each name in `TOPICS` (`work`, `ops`, `vocabulary`, `findings`); the values are the exact strings the handler uses today (`WORK`, the ops text, the vocabulary builder, `FINDINGS`). `guide.ts` then reads the text from `TOPIC_TEXT[name]`. The type of `TOPIC_TEXT` is `Record<(typeof TOPIC_NAMES)[number], …>`, so a topic without text fails the compiler: derive the name union from the entries you write. `list.ts` takes its kind names from `LIST_KINDS` (already a registry) and dispatches on the resolved name, not on a literal string. Behaviour and all messages stay the same.

Test (`e2e/connector-topics.spec.ts`, new, pure): `TOPIC_TEXT` has a non-empty string for every name in `TOPICS.names()`; `guide` answers for each topic name without `unknown-name`.
