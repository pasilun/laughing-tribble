Rewritten 2026-11-11 by the spec author after the run that blocked it (its reasons were right: the line numbers were wrong and the card left two choices open). `list.ts` is fine as it is and is no longer part of this card.

Defect: the `guide` handler holds the topic texts and a `switch` whose `default` returns the working order, so a topic added to `TOPICS` without text answers silently with the wrong text.

Do: each topic carries the function that writes it, and the handler has no switch.

1. New file `lib/plan/connector/registries/topics.ts`:
```ts
import type { Entry, Registry } from '../names'
import { Registry as Reg } from '../names'
import { OPERATIONS } from './operations'
import { OPS_DOC } from '../../mcp/ops-docs'

// What a topic gives: the text for Claude, and data for programs.
export type TopicText = { summary: string; data?: Record<string, unknown> }
// `families` is passed in by the caller (FAMILIES from ./index), which avoids an import cycle.
export type TopicEntry = Entry & { text: (families: Record<string, Registry<Entry>>) => TopicText }

const WORK = `…`      // move the exact WORK string from handlers/guide.ts
const FINDINGS = `…`  // move the exact FINDINGS string from handlers/guide.ts

export const TOPICS = new Reg<TopicEntry>('topics', 'ämne', [
  { name: 'work', summary: 'The working order', text: () => ({ summary: WORK }) },
  { name: 'ops', summary: 'The operations of edit, with fields and examples',
    text: () => ({ summary: `Operationer: ${OPERATIONS.names().join(', ')}\n\n${OPS_DOC}` }) },
  { name: 'vocabulary', summary: 'Every name the connector knows, by family',
    text: (families) => ({
      summary: Object.entries(families).map(([k, r]) => `${k}: ${r.names().join(', ') || '–'}`).join('\n'),
      data: { families: Object.fromEntries(Object.entries(families).map(([k, r]) => [k, r.names()])) },
    }) },
  { name: 'findings', summary: 'The shape of a finding and the standard codes', text: () => ({ summary: FINDINGS }) },
])
export const WORK_TEXT = WORK
```
2. `lib/plan/connector/registries/index.ts`: delete the `TOPICS` declared there and `export { TOPICS } from './topics'` (import it too, for `FAMILIES`). `FAMILIES.topics` stays `TOPICS` (cast to `Registry<Entry>` as for `OPERATIONS`).
3. `lib/plan/connector/handlers/guide.ts`: remove `WORK`, `FINDINGS`, the `OPS_DOC` and `OPERATIONS` imports and the `switch`. With no topic: summary `${WORK_TEXT}\n\nÄmnen: …` and `data.topics` as today. With a topic: resolve it with `TOPICS`, then `const t = entry.text(FAMILIES)` and answer `ok(t.summary, t.data)`. The answers must be exactly what they are today: same summaries, and `data.families` for `vocabulary` (the other topics now return no `data`, as today; the current handler gives no `data.topic`).

Test (`e2e/connector-topics.spec.ts`, new, pure): for every entry of `TOPICS`, `entry.text(FAMILIES).summary` is a non-empty string; `TOPICS.get('vocabulary')!.text(FAMILIES).data!.families` has the key `operations`. The existing `e2e/connector-guide.spec.ts` must pass unchanged: it is the check that the answers did not change.
