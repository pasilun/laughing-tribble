Defect (checkpoint S2-R2, reviewer): `view` returns the picture but no `data.image` (`mm_per_px`, `origin_mm`, `size_px`), which contract §4 asks for, and it ignores `max_tokens` (contract §3): `maxPx` is fixed at 1400 (`view.ts` around line 80).

Blocked: the contract's meaning of `max_tokens` (what it sizes, and how a token budget maps to pixels) and the exact `data.image` fields are not written down in §3 and §4 as read by the reviewer. Needs the contract text settled first; set ready with attempts 0 after.

## Decided and rewritten 2026-11-11 by the spec author (committed to the repo)
Decision (the contract text is added to `docs/mcp-contract.md` §3 by this card): `max_tokens` is the size budget of a picture in tokens, where a token is 28×28 pixels: the long side of the picture is `round(28 × √max_tokens)` pixels, at most 2576 (so the default 1600 gives 1120 px). It applies to the views `overlay` and `source`; the sheet view has a fixed size. `data.image` is `{ size_px: [w, h], mm_per_px, origin_mm: [x, y] }`: `mm_per_px` and `origin_mm` (plan mm of the picture's top-left corner) only for overlay and source, `size_px` for every picture.

In `lib/plan/connector/handlers/view.ts`:
1. After the line that validates `args.options` add: `  if (args.max_tokens !== undefined && (typeof args.max_tokens !== 'number' || !Number.isInteger(args.max_tokens) || args.max_tokens < 1)) return fail([badArgument('max_tokens', 'ska vara ett positivt heltal')])`.
2. A helper above `view`: `const sizeOf = (png: Buffer): [number, number] => [png.readUInt32BE(16), png.readUInt32BE(20)]` (the width and height in a PNG header).
3. In the `sheet` branch, replace `return done(await preview(plan, sheetView, false), `Revision ${rev.meta.n}`)` with
```ts
    const img = await preview(plan, sheetView, false)
    return done(img, `Revision ${rev.meta.n}`, { image: { size_px: sizeOf(Buffer.from(img.data, 'base64')) } })
```
4. In the overlay/source branch replace `maxPx: 1400` by `maxPx: Math.min(2576, Math.max(100, Math.round(28 * Math.sqrt((args.max_tokens as number | undefined) ?? 1600))))` and replace the data argument `{ rect_mm: [rect.x, rect.y, rect.w, rect.h], source: sid }` by
`{ rect_mm: [rect.x, rect.y, rect.w, rect.h], source: sid, image: { size_px: sizeOf(v.png), mm_per_px: Math.round((1 / v.scale) * 10000) / 10000, origin_mm: [rect.x, rect.y] } }`.

Contract text: in `docs/mcp-contract.md` §3, in the table row for `max_tokens`, replace "Size budget of a picture. Default 1600." by the sentence above (budget in tokens, 28×28 px each, long side `round(28·√tokens)` px, at most 2576, default 1600, for overlay and source). Do not touch any tool description or schema (the list is frozen).

Tests, added at the end of the first `view` test in `e2e/connector-view.spec.ts`, after the overlay assertions (the plan `id` has the source `arkiv` there):
```ts
  const w = (await connector(request, 'view', { id, view: 'overlay', region: { rect_mm: [0, 0, 3000, 2000] } })).structuredContent!.data!.image as { size_px: number[]; mm_per_px: number; origin_mm: number[] }
  expect(Math.max(...w.size_px)).toBe(1120); expect(w.mm_per_px).toBeCloseTo(3000 / 1120, 3); expect(w.origin_mm).toEqual([0, 0])
  const small = (await connector(request, 'view', { id, view: 'overlay', max_tokens: 400, region: { rect_mm: [0, 0, 3000, 2000] } })).structuredContent!.data!.image as { size_px: number[] }
  expect(Math.max(...small.size_px)).toBe(560)
  const sheetImage = (await connector(request, 'view', { id })).structuredContent!.data!.image as { size_px: number[] }
  expect(sheetImage.size_px.length).toBe(2)
  expect((await connector(request, 'view', { id, max_tokens: 0 })).structuredContent!.findings![0].code).toBe('bad-argument')
```
