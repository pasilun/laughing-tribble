Defect (checkpoint S2-R2, reviewer): `manage` `create` with an unknown `template` silently becomes `'empty'` (`manage.ts` around line 117). Contract §5 says an unknown name is an `unknown-name` finding with the valid names and the nearest match.

Do: in `registries/index.ts` add an exported registry `TEMPLATES` (do NOT add it to `FAMILIES`: that would change the frozen families list checked by `e2e/connector-registries.spec.ts`):
```ts
export const TEMPLATES = new Registry<Entry>('templates', 'mall', [
  { name: 'empty', summary: 'A new, empty plan (default)' },
  { name: 'demo', summary: 'A plan with a demo drawing' },
])
```
In `manage.ts`, in the `create` branch: if `a.template` is `undefined`, use `'empty'`. Otherwise resolve it with `TEMPLATES.resolve(String(a.template))`; a finding is returned with `fail([r.finding])`; otherwise use `r.entry.name` as the template. Nothing else in `create` changes. The sheet default for `view`/`export` is NOT part of this card.

Test (`e2e/connector-templates.spec.ts`, new, API): `manage { action: 'create', args: { name: 'Mall test ' + Date.now(), template: 'demo' } }` is ok true; `template: 'dmo'` gives `findings[0].code === 'unknown-name'` and `findings[0].data.nearest === 'demo'`; with no template the call is ok true.
