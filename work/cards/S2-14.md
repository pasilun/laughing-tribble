Do: `list`: the person's documents, and the revisions of one. Read `plan_list` and `plan_revisions` in `lib/plan/mcp/tools-read.ts`; do not change them. (Site plans join later, with `manage`.)

`lib/plan/connector/handlers/list.ts`: `export async function list(args: Args): Promise<ToolResult>`; every return is `toToolResult(answer(…), { summary })`.

Steps:
1. **Arguments:** `what`, `id`, `query`, `cursor` strings when given; `limit` an integer when given (clamp to 1…200, default 50). Otherwise `badArgument`.
2. **what:** `LIST_KINDS.resolve(what ?? 'plans')` (from `../registries`); a finding is answered with `ok: false`.
3. **plans:** `listPlans()` from `../../storage/store`. Keep the items whose name or any tag contains `query` (case-insensitive) when `query` is given. `cursor` is the offset as a string (default `'0'`; not a number is `badArgument('cursor', …)`). `items` = the slice `[offset, offset + limit)`, each `{ id, name, revision, issued, tags, owner, sharedWith }` (leave out undefined keys). `data: { items }`, plus `data.next_cursor = String(offset + limit)` when more items remain. Summary: one line per item as `plan_list` writes it, or `Inga dokument.`
4. **revisions:** needs `id` (else `badArgument('id', 'krävs')`); `listRevisions(id)` from `../../storage/store`; an empty result for an unknown plan is `notFound(id)`. `data: { items: [{ n, author, message, createdAt, issued?, by? }] }`, newest first; summary one line per revision: `rev ${n} ${createdAt} ${author}${by ? ' (' + by + ')' : ''}: ${message}`. `limit` and `cursor` apply as for plans.

In `lib/plan/connector/handlers/index.ts` replace the `list` entry. Change nothing else there.

Tests (`e2e/connector-list.spec.ts`, API tests; `makePlan` gives a unique name that starts with the text you pass):
- create two plans `a = makePlan(request, 'Listtest Alfa')` and `b = makePlan(request, 'Listtest Beta')`.
- `list {}` → `ok: true`; `data.items` contains an item with `id === a.id` and one with `id === b.id`; the item has `revision: 1`.
- `list { query: 'listtest alfa' }` → contains `a.id` and not `b.id`.
- `list { limit: 1 }` → `data.items.length === 1` and `data.next_cursor` is a string.
- `list { what: 'revisions', id: a.id }` after one edit with the old `plan_edit` → `data.items.length === 2`, `data.items[0].n === 2`.
- `list { what: 'revisons', id: a.id }` → `findings[0].data.nearest === 'revisions'`.
- `list { what: 'revisions' }` → `findings[0].code === 'bad-argument'`.
- `list { what: 'revisions', id: 'no-such-plan' }` → `findings[0].code === 'not-found'`.
