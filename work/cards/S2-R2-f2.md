Defect (checkpoint S2-R2, reviewer): `audit` (`checks/index.ts` around line 108) gives the code `audit-${i.id.split(':')[0]}`, so `no-entrance`, `no-source` and `warnings` all get the code `audit-plan`. Two findings share the id `plan:no-entrance` (seen live).

Blocked: needs a design choice. The audit's own item ids collide (the same id for different causes), so a fix has to decide whether to hash the message (as S2-R1-f2 did for checks), append an index, or change `lib/plan/assist/audit.ts` (which needs an authorisation). Set ready with attempts 0 only after the decision is written here.

## Decided and rewritten 2026-11-11 by the spec author (committed to the repo)
Decision: an audit finding keeps the audit's own id (`wall:w3`, `plan:no-entrance`); when the same id occurs again in one answer, the later ones get `#2`, `#3` in order (so ids are unique per answer and stable between calls on the same plan). The code is `audit-plan-<rest>` for ids of the form `plan:<rest>` (`audit-plan-no-source`, `audit-plan-no-entrance`) and `audit-<kind>` for the others (`audit-wall`, `audit-door`, `audit-opening`). Nothing in `lib/plan/assist/` changes.

In `lib/plan/connector/checks/index.ts`, in the `audit` entry, replace the statement that starts `    return { findings: items.map((i) => finding({ id: i.id, code: `audit-${i.id.split(':')[0]}`` (it is the last statement of `run`; the line may be long) with:
```ts
    const used = new Map<string, number>()
    const codeOf = (id: string) => {
      const [kind, ...rest] = id.split(':')
      return kind === 'plan' && rest.length ? `audit-plan-${rest.join('-')}` : `audit-${kind}`
    }
    return {
      findings: items.map((i) => {
        const n = (used.get(i.id) ?? 0) + 1
        used.set(i.id, n)
        return finding({
          id: n === 1 ? i.id : `${i.id}#${n}`,
          code: codeOf(i.id),
          level: i.level,
          message: i.text,
          refs: [i.id],
          ...(i.fix ? { fix: i.fix as Array<Record<string, unknown>> } : {}),
          ...(i.fixText ? { data: { fix_text: i.fixText } } : {}),
        })
      }),
    }
```
(keep the closing `  } }` of the entry as it is).
