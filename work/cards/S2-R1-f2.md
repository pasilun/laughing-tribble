Defect (checkpoint S2-R1, reviewer): `fromCheck` gives a check finding without a ref the id = its code (`lib/plan/connector/findings.ts:7`). Two causes with the same code then share one id. Seen live: one edit returned two findings both with id `title-block`.

Do: in `fromCheck`, when the check finding has no ref, make the id `${code}:${h}` where `h` is a short stable hash of the message: a 6-character hex from a simple FNV-1a 32-bit over the UTF-8 string (write it as a private function; no dependency). A finding with a ref keeps `${code}:${ref}`. The `finding()` helper and the existing contract (id stable for the same cause) do not change.

Test (`e2e/connector-finding-ids.spec.ts`, new, pure): two check findings with code `title-block` and different messages give two different ids; the same finding twice gives the same id; a finding with `ref: 'v1'` keeps `title-block:v1`.
