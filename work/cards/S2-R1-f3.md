Defect (checkpoint S2-R1, reviewer): refused answers leave out `id` and `revision` even when the code knows them (`edit.ts:17`, and the failure returns in `get.ts` and `list.ts`). A stale-revision answer has the current revision only in `data.current`.

Do: in every `ok: false` answer where the handler already knows the plan id, pass `id` to `answer(…)`. Where the handler knows the current revision (the stale case in `edit`, and `get` after loading the plan), pass `revision` too. Do not change the finding objects, the summaries or any `data` key. Successful answers do not change.

Test (`e2e/connector-refused.spec.ts`, new, API): create a demo plan with `makePlan` (revision 1), save one edit through the old `plan_edit` (revision 2). Then `edit { id, base_revision: 1, ops: [] }` gives `structuredContent.id === id` and `structuredContent.revision === 2`, and `findings[0].data.current === 2`. `get { id: 'no-such-plan' }` gives `id` equal to `no-such-plan`, and no `revision` key.

Done when: `npm run typecheck && npm run lint && CI=1 npx playwright test e2e/connector-refused.spec.ts e2e/connector-edit.spec.ts --reporter=line 2>&1 | tail -40` passes.
