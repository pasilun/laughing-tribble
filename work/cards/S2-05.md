Do: list the plan operations in a registry, so that `guide` can name them and `edit` can check a name before applying anything. The operations themselves stay in `lib/plan/domain/ops.ts`; do not change that file.

`lib/plan/connector/registries/operations.ts`:
```ts
import type { Op } from '../../domain/ops'
import { Registry, type Entry } from '../names'

export type OperationEntry = Entry & { example: Op }

// `Record<Op['op'], …>` makes the compiler fail when an operation is added to ops.ts and not listed here.
const DEFS: Record<Op['op'], { summary: string; example: Op }> = { … }

export const OPERATIONS = new Registry<OperationEntry>('operations', 'operation',
  Object.entries(DEFS).map(([name, d]) => ({ name, ...d })))
```
The eleven entries, with these summaries and examples (every example is valid on `demoPlan()`; checked by the spec author):

| name | summary | example |
|---|---|---|
| add | Add a wall, mass, zone, opening, fixture, room, dimension, note or source | `{ op: 'add', kind: 'note', item: { id: 'n-test', at: { x: 1000, y: 1000 }, text: 'Test' } }` |
| update | Change fields of one element by id | `{ op: 'update', kind: 'opening', id: 'ny-oppning', patch: { width: 1000 } }` |
| delete | Remove one element (a wall takes its openings with it) | `{ op: 'delete', kind: 'fixture', id: 'kok-b' }` |
| moveVertex | Move every wall end at a point; joined walls follow | `{ op: 'moveVertex', from: { x: 6000, y: 0 }, to: { x: 6000, y: 100 } }` |
| moveWall | Move a wall by dx, dy; walls joined at its ends stretch | `{ op: 'moveWall', id: 'a-hall', dx: 0, dy: 100 }` |
| setWallLength | Change a wall's length, keeping one end fixed | `{ op: 'setWallLength', id: 'a-hall', length: 3400, fixed: 'a' }` |
| scale | Scale the whole drawing about a point, separately along x and y | `{ op: 'scale', origin: { x: 0, y: 0 }, fx: 1.01, fy: 1.01 }` |
| setName | Rename the document | `{ op: 'setName', name: 'Nytt namn' }` |
| setSheet | Change paper, orientation, scale or north angle | `{ op: 'setSheet', patch: { scale: 100 } }` |
| setTitleBlock | Change title block fields | `{ op: 'setTitleBlock', patch: { author: 'Test' } }` |
| setUnderlay | Set or clear the underlay image (used by the editor; sources replace it for Claude) | `{ op: 'setUnderlay', underlay: null }` |

Tests (`e2e/connector-operations.spec.ts`, pure):
- `OPERATIONS.names()` equals the eleven names above in that order.
- For each entry, `applyOps(demoPlan(), [entry.example])` returns `errors` equal to `[]`.
- For each name except `setUnderlay`, `OPS_DOC` (from `lib/plan/mcp/ops-docs.ts`) contains `"op":"${name}"` (the reference text lists every operation but that one, which the editor uses and Claude does not; do not edit `ops-docs.ts`).
- `OPERATIONS.resolve('moveWal')` gives a finding with `data.nearest === 'moveWall'`.
