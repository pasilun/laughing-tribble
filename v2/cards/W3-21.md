These are the v1 permit checks (`lib/plan/domain/checks.ts`: codes load-bearing, fire, opening-height) that the v2 model can express. They are advice for the permit application, so they are **not** part of `resolve` or `plan check`.

```rust
/// Permit review of a resolved plan: what the application will need. Pure.
pub fn review(resolved: &Resolved) -> Vec<Diagnostic>
```
Order of the result: first walls in id order (`resolved.walls` is a BTreeMap), for each wall W030 then W031; then openings in id order, for each opening W032, W033, I030.

Rules (args as in the W3-01 templates; `span: None`):
- **W030** (Warning): `wall.bearing && wall.phase == Demolish`. refs [wall id]. data `{"wall": id}`.
- **W031** (Warning): `wall.fire == Some(f) && wall.phase == Demolish`. refs [wall id]. data `{"wall": id, "fire": f}`.
- For an opening with `phase == New`, with `w` = its wall (`resolved.walls.get(&opening.wall)`; skip the wall rules when missing) and kind word `Door`, `Window` or `Passage`:
  - **W032** (Warning): `w.bearing && w.phase != Demolish`. refs [opening id, wall id]. data `{"opening": id, "wall": wall id}`.
  - **W033** (Warning): `w.fire == Some(f) && w.phase != Demolish`. refs and data as W032 plus `"fire": f`.
  - **I030** (Info): `opening.height == None`. refs [opening id]. data `{"opening": id}`.

Test (review.rs test module, fixture `review-1`): exactly these four, in this order:
1. W030 `Wall W:A.east|B.west is load-bearing and is demolished; this needs a structural engineer's drawings and calculation.`
2. W031 `Wall W:A.east|B.west is a fire-cell boundary (EI60) and is demolished; a fire protection description is required.`
3. W032 `Door O:A.north:1 is new and sits in load-bearing wall W:A.north:outer; this needs a structural engineer's statement.`
4. I030 `Door O:A.north:1 is new and has no height; add "height <mm>" if the engineer needs it.`
(The window has a height and its wall is plain, so it gives nothing.) Fixture A gives an empty list.
