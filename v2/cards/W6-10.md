Do: Every write to a plan appears in the history, including the ones that do not come from `apply`.

**`crates/server/src/assets.rs`** (`add_source`): add an `author: &str` parameter (`"claude"` from the tool, `"upload"` from the upload page) and save through `save_logged` with
`Entry { patch: <the source line that was added>, changes: 1, summary: "Added source <name>." , .. }`. The returned JSON gains `rev`.

**`source_calibrate`** (`crates/server/src/lib.rs`): save through `save_logged` with the replace patch (`- old` / `+ new`), `changes: 1`, `summary: "Calibrated source <name>."`, author `"claude"`; its JSON already carries `rev` — keep it. `dry_run` writes nothing.

**`upload`** calls `add_source` with `author: "upload"`; the page's success text names the source and the revision.

**`get`**:
- `json`: add `"rev": <current>` at the top level (0 when no history); `fields` still filters the geometry groups.
- `summary`: the first line becomes `plan "<id>" (rev N)`; the source lines are unchanged.
- `check` JSON also gains `rev`.

Tests:
- `apply` → `source_add` → `source_calibrate` → `history` shows three entries in order with authors `claude`, `claude`, `claude`; upload adds one with `upload`;
- `get json` and `check` report the same `rev` as `history`;
- a failed `source_add` (E024) adds no entry and does not change `rev`.

Done when: the tests pass and the workspace gate is green.

Amended 2026-11-11 by the spec owner (authorisations committed to the repo; they add to the card and change nothing else in it):
- Adding `rev` to the `get` and `check` JSON may change existing expectations of those results; authorised: add the `rev` key to those expectations and nothing else.
