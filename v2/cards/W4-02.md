Files: `v2/crates/core/src/resolved.rs`, `v2/crates/core/src/lib.rs` (re-export `resolve_draft`).

Why: `resolve` returns no geometry when an E003 exists, so a conflict cannot be shown in a picture.

Do: move the body of `resolve` into `fn resolve_with(plan: &Plan, draft: bool) -> (Option<Resolved>, Vec<Diagnostic>)`. `resolve(plan)` calls it with `false` and behaves exactly as today. `pub fn resolve_draft(plan)` calls it with `true`. In draft mode every "stop on error" test uses this instead of `has_error`:
```rust
/// Errors that leave nothing to draw: bad sizes, self relations, non-parallel measures, overlapping rooms.
fn stops_draft(diagnostics: &[Diagnostic]) -> bool {
    diagnostics.iter().any(|d| matches!(d.code, Code::E014 | Code::E015 | Code::E010 | Code::E005))
}
```
So in draft mode an axis with E003 keeps its first-pass coordinates (the least-squares step is already skipped for such an axis), and opening errors (E004, E007, E013, E016, E017) leave those openings as `place_openings` returns them. The returned `Resolved.diagnostics` and the returned vector hold every diagnostic, errors included.

Tests (resolved.rs test module):
- fixture B: `resolve` → `None` (as before); `resolve_draft` → `Some`, Sovrum south = 4540, Garderob north = 0, and the diagnostics contain one E003.
- fixture C: `resolve_draft` → `Some`, Sovrum south 4540, Vardagsrum south 4593.
- fixture A: `resolve_draft` equals `resolve` (same `Resolved`, same diagnostics).
- `room A 0 x 2000 source laser`: `resolve_draft` → `None`.
