**Asset helpers** in `crates/scan/src/assets.rs` (used by the server now and the CLI in W6-11):
```rust
/// A source asset is <root>/sources/<plan_id>/<source_name>.png
pub fn asset_dir(root: &Path, plan_id: &str) -> PathBuf;
pub fn asset_path(root: &Path, plan_id: &str, source_name: &str) -> PathBuf;

pub fn safe_file_name(name: &str) -> Result<String, String>;

```

**Server module** `crates/server/src/assets.rs` (new), shared by the tool and the upload page:
```rust
pub struct AddSource {
    pub plan_id: String,
    pub upload_file: String,      // a file name under <root>/uploads/
    pub original_name: Option<String>,
    pub name: Option<String>,
    pub scale: Option<u32>,
    pub dpi: Option<f64>,
    pub mm_per_px: Option<i64>,   // thousandths
    pub at: Option<(i64, i64)>,
    pub role: Option<String>,     // archive | before | after | other
    pub year: Option<i32>,
    pub view: Option<String>,     // plan | elevation
}
pub fn add_source(store: &Store, a: AddSource) -> Result<serde_json::Value, Vec<Diagnostic>>;
```
Steps, in order:
1. `uploads/<upload_file>` must exist and be a plain file; max 30 MB; otherwise **E024**.
2. Read and `plan_scan::decode::decode`: an error becomes E024 with its reason.
3. `mm_per_px`: explicit `mm_per_px`, else `mm_per_px_from(scale, dpi)` when both are present, else `None` (uncalibrated). Also use the decoded `dpi` with `scale` when only the DPI is used.
4. Load and parse the plan (E006/E020 as elsewhere). `name` = the given name or `free_source_name(stem of the original file, existing names)`.
5. Build the `source` statement (canonical text, D50) and apply it with `plan_core::apply(&plan, &line, false)`. If `!ok`, return the diagnostics and write no asset.
6. `plan_scan::assets::write_asset(asset_path(...), &decoded.png)`; E024 if writing fails.
7. Save the plan (with the history entry once W6-09 exists; for now `Store::save`).
8. Return `{plan_id, name, file, width_px, height_px, dpi, mm_per_px, at, role, year, view, calibrated, saved}`.

**Tool** `source_add {plan_id, file, name?, scale?, dpi?, mm_per_px?, at?: [i64;2], role?, year?, view?}` in `crates/server/src/lib.rs`: calls `add_source`; a decoded `dpi` is returned but not written to the DSL.

**`get`** gains `Field::Sources`; `json` adds a `sources` array (`name, file, width_px, height_px, mm_per_px, at, role, year, view, calibrated`) by reading each asset's pixel size with `plan_scan::png_size` (no re-conversion). `summary` adds one line per source: `source ark: ark-1936.png 4200×3000 px, 6.35 mm/px, at 0,0, role archive, year 1936` (or `not calibrated`).

**Diagnostics** (`crates/core/src/diagnostics.rs`): add
`E024 Source "{name}" could not be read: {reason}.` (severity error, refs `[name]`).

Tests:
- temp root; write a 4×3 PNG to `<root>/uploads/scan.png`; `add_source` returns the dims, the plan text has `source scan "scan.png"` (plus `mm_per_px 12700` when scale 100 and dpi 200 are given), and `<root>/sources/<plan>/scan.png` exists;
- a second `add_source` with the same name gets `scan-2`;
- a missing upload and a text file give E024 with `reason`;
- `get view=json fields=[sources]` lists the source and `get view=summary` prints its line.
