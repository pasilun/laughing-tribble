Files: `v2/crates/core/src/intent.rs`, `dsl/lexer.rs`, `dsl/parser.rs`, `dsl/printer.rs`, `commands.rs`, `v2/crates/core/tests/common/mod.rs` (generator), struct literals of `Plan` in tests (mechanical).

Grammar (D41): `title = "title" KEY STRING`, where KEY is one of `property`, `address`, `applicant`, `drawing`, `drawn_by`, `date`, `description`. `title` is a new keyword; the keys are ordinary words read after it (they are **not** keywords, so a room may be called `date`). An unknown key is E006: expected `a title key (property, address, applicant, drawing, drawn_by, date, description)`.

Do:
1. intent.rs: `Plan` gains `pub title: BTreeMap<String, String>` (key → text), same serde style as the other fields, with `#[serde(default)]`.
2. Parser: statement `title`; a repeated key replaces the earlier value. Lexer: the keyword.
3. Printer: the title lines come right after the two default lines and before the first room, in the key order listed above (not alphabetical), as `title {key} "{text}"`. If a blank line separates the defaults from the rooms today, the title lines go before that blank line.
4. commands.rs patch semantics (§10.1): a `title` statement's key is its KEY; it replaces or adds; `- title drawing "x"` removes that key (the text is ignored when removing).
5. Generator (authorised): `title` is a map with zero to two entries drawn from the seven keys, values from a small fixed set without double quotes (for example `"Gnejsen 6"`, `"A-01"`, `"2026-11-10"`). Other `Plan { … }` literals in tests get `title: BTreeMap::new()` (authorised, mechanical).

Tests (parser, printer, commands test modules):
- `title property "Stockholm Gnejsen 6"` and `title drawing "A-01"` parse into the map; printing gives them in the order property, drawing, right after the defaults.
- `title colour "red"` → E006 with the expected text above.
- patch `title drawing "A-02"` replaces; patch `- title drawing ""` removes.
- fixtures A, B, C print exactly as before (no title lines); the round-trip proptest passes.

Done when: the tests pass, the fixtures' expected JSON still match, and `cd v2 && cargo fmt --check && cargo clippy -q -- -D warnings && cargo test -q` is green.
