Why: week one keeps first-pass values and says so in W004 (W1-14). Now the solver spreads the difference instead.

Files: the solver function W1-14 changed (find it with `grep -rn "W004" v2/crates/core/src/solve`), `v2/crates/core/src/report.rs` (`solve_json`), new fixtures `v2/fixtures/dist-1.plan` and `v2/fixtures/dist-1.expected.json` (this card authorises creating them), and the one W1-14 test named below.

Rule, per axis, after the cycle check (W1-12):
1. If any CycleCheck on the axis has `conflict == true`: do nothing new (E003 path, plan does not resolve).
2. Else, for each component that has a CycleCheck with `residual != 0`: call `distribute(edges, component, axis, &coords)` and replace that component's coordinates with `Distribution.coords`. If `distribute` returns `None`, keep the first-pass coordinates (no new diagnostic).
3. Emit **one** W004 per axis that distributed anything, listing every AdjustedEdge with `|shift| > 0.5`, in edge-index order, as `{origin} {value}→{adjusted}` joined by `", "`. Message: `message(Code::W004, &[("list", list)])`. `refs`: the origins. `data`: `{"axis": "x"|"y", "adjusted": [{"origin": …, "value": …, "adjusted": …}, …]}` (same edges, same order).
4. If no edge moved more than 0.5 mm, emit no W004.
5. This replaces the week-one W004 "kept first-pass values". **Authorised test edit:** update the expected text of the W1-14 test (the synthetic within-tolerance cycle) to the new list form, and only that string; the test must still assert W004 and no E003.

`solve_json`: when a W004 is present, add a top-level key `"adjusted"` with the concatenated `data.adjusted` arrays of all W004s (x first, then y). Leave the key out when there is no W004. The spec lists this key in §7.7.
