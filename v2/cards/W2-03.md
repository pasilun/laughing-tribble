Why: P1-08. Within-tolerance cycles are spread over the edges by weighted least squares, so the edge with the largest tolerance absorbs most of the difference. This card is only the maths, on plain indices; W2-04 maps faces to indices.

Dependency: add `nalgebra = "0.35"` to `v2/crates/core/Cargo.toml` `[dependencies]` (listed in agent specs §4). No other dependency.

Files: create `v2/crates/core/src/solve/lsq.rs`; add `pub mod lsq;` to `solve/mod.rs`.

Interface (write exactly this):

```rust
/// A soft equation x[b] − x[a] ≈ value with weight (1 / tol²).
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct Soft { pub a: usize, pub b: usize, pub value: f64, pub weight: f64 }
/// A hard equation x[b] − x[a] = value.
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct Hard { pub a: usize, pub b: usize, pub value: f64 }

/// Weight for an edge tolerance in mm: 1 / max(tol, 1)².
pub fn weight(tol: Mm) -> f64;

/// Minimise Σ w (x[b] − x[a] − v)² over `soft`, subject to `hard` and to
/// x[i] = v for each `(i, v)` in `fixed`. `n` unknowns. Returns `None` when
/// the system is singular (some unknown is not reached by any equation).
pub fn wls(n: usize, fixed: &[(usize, f64)], soft: &[Soft], hard: &[Hard]) -> Option<Vec<f64>>;
```

Code (verified by the spec owner with nalgebra 0.35.0; use it as is, then add doc comments):

```rust
use nalgebra::{DMatrix, DVector};

pub fn wls(n: usize, fixed: &[(usize, f64)], soft: &[Soft], hard: &[Hard]) -> Option<Vec<f64>> {
    let m = fixed.len() + hard.len();
    let mut k = DMatrix::<f64>::zeros(n + m, n + m);
    let mut rhs = DVector::<f64>::zeros(n + m);
    for e in soft {
        let w2 = 2.0 * e.weight;
        k[(e.a, e.a)] += w2;
        k[(e.b, e.b)] += w2;
        k[(e.a, e.b)] -= w2;
        k[(e.b, e.a)] -= w2;
        rhs[e.a] -= w2 * e.value;
        rhs[e.b] += w2 * e.value;
    }
    let mut row = n;
    for &(i, v) in fixed {
        k[(row, i)] = 1.0;
        k[(i, row)] = 1.0;
        rhs[row] = v;
        row += 1;
    }
    for e in hard {
        k[(row, e.b)] = 1.0;
        k[(row, e.a)] = -1.0;
        k[(e.b, row)] = 1.0;
        k[(e.a, row)] = -1.0;
        rhs[row] = e.value;
        row += 1;
    }
    let sol = k.lu().solve(&rhs)?;
    Some((0..n).map(|i| sol[i]).collect())
}
```

Indexing a `DMatrix` with `k[(r, c)]` panics only on an out-of-range index. Guard against that: return `None` at the start if any index in `fixed`, `soft` or `hard` is `>= n`. That keeps rule 6 (no panic in library code).
