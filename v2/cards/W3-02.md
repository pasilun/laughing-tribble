Files: new `v2/crates/core/src/validate.rs`; `v2/crates/core/src/lib.rs` (add `pub mod validate;`); `v2/crates/core/src/resolved.rs` (call it).

Problem found by the audit: `room A 0 x 2000` is accepted and drawn as a zero-width room, and `A east_of A gap` gives a confusing E003.

Do:
1. `pub fn validate(plan: &Plan) -> Vec<Diagnostic>` in validate.rs. Every diagnostic: severity Error, `span: None`, `data: json!({})`, `refs` as stated. Checks, in this order:
   - `default_wall.value < 1` → E014, what = `default_wall`. Same for `default_outer_wall`. refs empty.
   - For each room in `plan.order`: width `Some(q)` with `q.value < 1` → E014, what = `Room {name} width`; then depth → what = `Room {name} depth`. refs = [room name].
   - For each relation in `plan.relations`, in order: EastOf/WestOf/SouthOf/NorthOf with `subject == of` → E015 with subject, relation (`east_of`, `west_of`, `south_of`, `north_of`) and of. refs = [room name]. `Align` is not checked.
   - For each opening in order: `width.value < 1` → E014, what = `{Kind} on {Room}.{side} width` where Kind is `Door`, `Window` or `Passage` and side is lower case (`Door on A.north width`). refs = [`{Room}.{side}`]. `at` may be 0.
   - For each wall override in order: thickness value < 1 → E014, what = `Wall {Room}.{side} thickness`. refs = [`{Room}.{side}`].
   - `value` is the number as decimal text.
2. In `resolve` (resolved.rs), first thing: `let mut diagnostics = validate(plan); if has_error(&diagnostics) { return (None, diagnostics); }` and then extend that vector with the edge diagnostics instead of creating a new one (`let (all_edges, edge_diags) = edges(plan); diagnostics.extend(edge_diags);`).

Tests (validate.rs test module, plans parsed with `crate::dsl::parse` or the helper the other tests in core use):

- `room A 3000 x 2000 source laser` + indented `east_of A gap` → exactly one, E015, `"A east_of A" relates a room to itself.`
- Fixture A (`include_str!("../../../fixtures/lgh154-a.plan")`) → empty.
- `resolve` on the first plan returns `None` and only the E014 (no E003, no I010).
