Files: `v2/crates/core/src/intent.rs`, `dsl/lexer.rs`, `dsl/parser.rs`, `dsl/printer.rs`, `build/walls.rs`, `validate.rs`, `commands.rs` (only if it stops compiling), `v2/crates/core/tests/common/mod.rs` (the generator).

Grammar (D34): `wall = "wall" face [ "thickness" INT [ src ] ] [ "bearing" ] [ "fire" STRING ] [ phase ]`, in that order, with at least one of the four parts. `bearing` and `fire` are new keywords (lower case; like the other keywords they cannot be room names).

Do:
1. intent.rs: `WallOverride` becomes
   ```rust
   pub struct WallOverride {
       pub face: FaceRef,
       pub thickness: Option<Quantity>,   // None: keep the default or the gap
       pub bearing: bool,                 // load-bearing
       pub fire: Option<String>,          // fire rating text, e.g. "EI60"
       pub phase: Phase,                  // existing unless stated
   }
   ```
   with the same derives and serde attributes as before.
2. Lexer: add the two keywords the way `thickness` is a keyword.
3. Parser `wall`: after the face, `thickness INT [src]` is optional (`cur.opt_kw("thickness")`), then `opt_kw("bearing")`, then `opt_kw("fire")` followed by a STRING (use the cursor method the `plan` and `apartment` statements use for a string), then `cur.phase().unwrap_or(Phase::Existing)`, then `cur.finish()`. If none of the four parts was present, return the E006 the cursor gives for "expected X, found Y" with expected `"thickness", "bearing", "fire" or a phase` at the position after the face.
4. Printer `wall_line`: `wall {face}` + ` thickness {n}{source clause}` if Some + ` bearing` if true + ` fire "{text}"` if Some + ` demolish`/` new` if not existing (the same words the opening line uses). Sort order unchanged.
5. walls.rs `outer_thickness`: use the override only when it has `thickness: Some(q)`; else the default.
6. validate.rs: the wall thickness check applies only to `Some`.
7. tests/common/mod.rs (authorised): the `wall_override` strategy builds `thickness: Some(qty)`, `bearing` any bool, `fire` either `None` or `Some("EI60".to_string())`, `phase` any of the three. Other struct literals of `WallOverride` in tests get `thickness: Some(…)`, `bearing: false`, `fire: None`, `phase: Phase::Existing` (authorised, mechanical).

Tests (parser and printer test modules):
- `wall A.north thickness 160 source laser` parses as before and prints the same line.
- `wall A.east bearing fire "EI60" demolish` → thickness None, bearing true, fire Some("EI60"), phase Demolish; prints the same line.
- `wall A.north bearing` → prints `wall A.north bearing`.
- `wall A.north` alone → E006.
- A room named `bearing` is rejected the way a room named `thickness` is.
- The round-trip proptest still passes with the new generator.

Done when: the tests pass, the fixtures' expected JSON still match, and `cd v2 && cargo fmt --check && cargo clippy -q -- -D warnings && cargo test -q` is green.
