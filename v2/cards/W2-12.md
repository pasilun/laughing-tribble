Why: an image costs ⌈w/28⌉ × ⌈h/28⌉ tokens; current Claude models take at most 2576 px on the long edge and 4784 tokens per image. A render is sized so it is never resized by the API, and the mm-per-pixel scale is a round number so the model (and a person) can read the grid.

Files: create `v2/crates/render/src/viewport.rs`; add `pub mod viewport;` to `v2/crates/render/src/lib.rs` (the crate exists since W1-23).

Interface (write exactly this):

```rust
pub const MAX_LONG_EDGE_PX: u32 = 2576;
pub const MAX_IMAGE_TOKENS: u32 = 4784;
pub const DEFAULT_TOKENS: u32 = 1600;

/// Mapping from plan mm to image pixels: px = (mm − origin_mm) / mm_per_px. x east, y south.
#[derive(Clone, Copy, Debug, PartialEq, serde::Serialize)]
pub struct Viewport { pub origin_mm: [i64; 2], pub mm_per_px: f64, pub size_px: [u32; 2], pub tokens: u32 }

/// Image tokens for a w × h px image: ceil(w/28) * ceil(h/28).
pub fn image_tokens(w: u32, h: u32) -> u32;

/// Smallest round scale that fits `[x, y, w, h]` (mm) into `max_tokens`.
pub fn fit(rect_mm: [i64; 4], max_tokens: u32) -> Viewport;
```

Pseudo-code:

```
budget = clamp(max_tokens, 1, MAX_IMAGE_TOKENS)
w_mm = max(rect.w, 1); h_mm = max(rect.h, 1)
for k in 0..=4:
  for m in [1.0, 1.25, 1.5, 2.0, 2.5, 3.0, 4.0, 5.0, 6.0, 8.0]:
    s = m * 10^k
    wpx = max(1, ceil(w_mm / s)); hpx = max(1, ceil(h_mm / s))
    if max(wpx, hpx) <= MAX_LONG_EDGE_PX and image_tokens(wpx, hpx) <= budget:
        return Viewport { origin_mm: [rect.x, rect.y], mm_per_px: s, size_px: [wpx, hpx], tokens: image_tokens(wpx, hpx) }
return the k = 4, m = 8.0 result (80 000 mm/px) computed the same way
```

Compute `10^k` as `10f64.powi(k)`; all candidate scales are exact in f64.
