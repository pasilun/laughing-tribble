Files: new `v2/crates/core/src/preview.rs`; `v2/crates/core/src/lib.rs` (`pub mod preview;`).

Why: a room that is not tied is drawn on top of the first room, so a picture of "what to measure" is misleading. The preview places it where the first suggestion says, only for the picture.

```rust
pub struct Preview {
    pub plan: Plan,                    // the plan with the assumed relations added
    pub assumed: Vec<Diagnostic>,      // the W001s that were used, in the order used
}
/// Add, for every room that is not tied, the relation its first W001 suggests (D39). Pure.
pub fn preview_missing(plan: &Plan) -> Preview
```
Algorithm (repeat at most `plan.order.len()` times):
1. `(_, diags) = resolve_draft(&current)`.
2. Take the first diagnostic with code W001 whose `data` has the keys `relation`, `of`, `room` and `gap` (the "Not tied" form; the "width/depth unknown" form has no `relation` and is skipped). None: stop.
3. Add to `current.relations` the placement relation it names: `relation` is `east_of`, `west_of`, `south_of` or `north_of`, subject = `room`, of = `of`, gap = `Gap::Wall` of `data.gap` mm with source `Assumed` and its default tolerance.
4. If, in the same `diags`, the same room also has a "Not tied" W001 on the **other** axis (`data.axis` is `"x"` or `"y"`), also add `Relation::Align { side, rooms: [of, room] }` with side North when the relation added in step 3 is east_of or west_of, and West when it is south_of or north_of.
5. Push the W001 of step 2 to `assumed`; go to 1.

Tests (preview.rs test module):
- rooms `A 2000 x 1000 source laser` and `B 1500 x 1000 source laser`, no relations: `assumed` has 1 entry (the east–west W001 for B); resolving `preview.plan` gives no W001; B is west 2090, east 3590, north 0, south 1000.
- fixture A: `assumed` is empty and `preview.plan == plan`.
- three rooms A, B, C with no relations: the loop ends, no W001 "Not tied" remains, and `assumed` has 2 entries.
