Files: `v2/crates/core/src/resolved.rs`.

Problem found by the audit: `measure … reference` parses and is ignored; nothing compares it with the drawing.

Do: in `resolve`, after the walls and openings are built and no error exists (just before `Resolved` is assembled), for each measure in `plan.measures` with `reference == true`, in order:
- Look up the solved coordinate of `from` and `to` (x map for east/west faces, y map for north/south faces; build the keys the way `rooms()` does). Skip the measure if a coordinate is missing or the faces are on different axes.
- `drawn = |coord(to) − coord(from)|`, `diff = |drawn − value.value|`.
- If `diff > value.tolerance`: push W020 (Warning) with args from, to (as `Room.side`, lower-case side), drawn, value, diff; `refs: [from, to]`; `data: json!({"from": …, "to": …, "drawn": drawn, "measured": value, "diff": diff})`.

Test (resolved.rs test module): fixture `dist-1` text with its last line replaced by `measure B.east to A.east = 520 source laser reference` (rooms A 2000 x 1000 and B 1500 x 1000, B south_of A, align west). Resolved is `Some`; diagnostics are exactly one W020: `Reference measure B.east→A.east: drawn 500, measured 520 (20 mm).` With `= 502` instead (laser tolerance 3): no diagnostic.

Done when: the tests pass, the fixtures' expected JSON still match, and `cd v2 && cargo fmt --check && cargo clippy -q -- -D warnings && cargo test -q` is green.
