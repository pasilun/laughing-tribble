Do: Port the `find` tool from the §11 schema.

**Core** `crates/core/src/api.rs`:
```rust
#[derive(Clone, Debug, PartialEq, Eq, Serialize)]
pub struct Found {
    pub id: String,
    pub kind: String,        // "room", "wall", "opening", "fixture", "stub"
    pub rect: RectMm,
    pub label: Option<String>, // rooms: the room name; others: the wall's `between` faces / opening kind
}
/// Case-insensitive search over `element_ids`. Exact (0), prefix (1), contains (2);
/// order by rank, then kind (room, wall, opening, fixture, stub), then id.
pub fn find(resolved: &Resolved, query: &str) -> Vec<Found>;
```
- An empty or whitespace-only query returns `[]`.
- A wall's `label` is `"<roomA>.<side>|<roomB>.<side>"` from `Wall.between` when present; an opening's label is its kind (`door`, `window`, `passage`); a fixture's its kind; a stub's `None`.
- `rect` comes from `element_rect`; skip an element with no rect.

**Server** tool `find {plan_id, query, limit?: usize (default 20)}`:
- load and resolve (E020/E021 as elsewhere; a plan that does not resolve returns its error diagnostics);
- `{ "plan_id", "query", "count", "matches": [{id, kind, rect, label}] }`;
- an empty result is `count: 0, matches: []`, not a tool error.

**CLI** `plan find FILE QUERY`: prints one line per match (`kind id [x,y,w,h] label`), then `N match(es)`; exit 1 on a parse/resolve error, 0 with no matches.

Tests:
- fixture A: `"vard"` finds `Vardagsrum` first; `"O:WC"` finds `O:WC.west:1`; `"w:"` finds walls; `""` returns `[]`; `"zzz"` returns `[]`;
- ranking: a plan with rooms `Hall` and `Hallway` — query `hall` puts `Hall` before `Hallway` (exact before prefix);
- server tool JSON has the limit applied;
- CLI output for `plan find fixtures/lgh154-a.plan vard` contains `room Vardagsrum`.
