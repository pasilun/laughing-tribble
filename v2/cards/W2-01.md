Why: the MCP server, the renderer and the CLI all need the same three steps (parse, check names, resolve). Put them in one place so the clients stay thin.

Files: create `v2/crates/core/src/api.rs`; add `pub mod api;` and `pub use api::{Resolve, load, resolve_plan};` to `v2/crates/core/src/lib.rs`. You may change the CLI (`v2/crates/cli/src/main.rs`) to call `load` instead of its own parse + resolve steps, if it has them; its snapshot tests must stay unchanged.

Interface (write exactly this):

```rust
/// A plan and what the kernel made of it. Lengths in mm, x east, y south.
#[derive(Clone, Debug, PartialEq, serde::Serialize)]
pub struct Resolve {
    pub plan: Plan,
    /// `None` when any Error diagnostic exists (§6.2 step 7).
    pub resolved: Option<Resolved>,
    /// All diagnostics from name resolution, solving and building, in the order the steps ran.
    pub diagnostics: Vec<Diagnostic>,
}

/// Resolve a plan that is already parsed. Never fails; errors are diagnostics.
pub fn resolve_plan(plan: &Plan) -> Resolve;

/// Parse DSL text, check names, and resolve. A parse error or name error
/// (E006, E001, E002) returns `Err` with those diagnostics and nothing else.
pub fn load(src: &str) -> Result<Resolve, Vec<Diagnostic>>;
```

Pseudo-code:

```
resolve_plan(plan):
    (resolved, diags) = crate::resolve(plan)          # W1-21's function
    Resolve { plan: plan.clone(), resolved, diagnostics: diags }

load(src):
    plan = crate::dsl::parse(src).map_err(|d| vec![d])?
    run the name check exactly as the CLI's `plan check` does it (W1-07 `resolve_names`
    with the refs the CLI collects); if it returns Err(ds) -> return Err(ds)
    Ok(resolve_plan(&plan))
```

If `plan check` collects name refs in the CLI crate, move that collection into a private fn in api.rs and make the CLI call `load`.
