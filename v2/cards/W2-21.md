Files: `v2/crates/server/src/lib.rs` (new tool), create `v2/crates/server/src/get.rs` for the view builders.

Arguments (serde + schemars; `rename_all = "lowercase"` on both enums):

```rust
#[derive(Debug, Default, serde::Deserialize, schemars::JsonSchema)]
pub enum GetView { #[default] Summary, Dsl, Json }
#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub enum Field { Rooms, Walls, Openings, Diagnostics }
#[derive(Debug, serde::Deserialize, schemars::JsonSchema)]
pub struct GetArgs {
    /// The plan: a file name under the server's root, without `.plan`.
    pub plan_id: String,
    /// summary (default): short text; dsl: the plan text; json: solved geometry.
    #[serde(default)] pub view: GetView,
    /// json view only: which parts to return; all when left out or empty.
    #[serde(default)] pub fields: Vec<Field>,
}
```

Tool: `#[tool(name = "get", description = GET_DESCRIPTION, annotations(read_only_hint = true))]`, `GET_DESCRIPTION = "Read a plan: summary (default), dsl (the plan text, to edit with apply) or json (solved faces, walls, openings, diagnostics)."`

Results (structured, via `tool_result` from W2-19):
- **dsl:** `{"plan_id", "view": "dsl", "text"}`. `text` = `plan_core::dsl::print` of the parsed plan. If the stored text does not parse: `text` = the stored text unchanged plus `"diagnostics": [...]` (not a tool error, so the model can see and fix it).
- **summary:** `{"plan_id", "view": "summary", "text"}`. Parse/name errors → tool error with those diagnostics. Text lines, joined by `\n`:
  1. `Plan "{name}": {n} rooms, resolved.` or `…, not resolved.`
  2. one line per room in declaration order: `{room} {w} x {d} mm, {area} m²` — when resolved, w = east − west, d = south − north from the solved faces and area = w·d/1e6 formatted `{:.2}`; when not resolved, the intent sizes with `?` for unknown and area `?`.
  3. `Walls: {walls}, openings: {openings}.` (counts from `Resolved`; 0 and 0 when not resolved)
  4. `Diagnostics: errors {e}, warnings {w}, info {i}.`
- **json:** `solve_json(plan_id, …)` filtered. Always keep `fixture` and `resolved`. Field → keys: rooms → `faces`, `areas_mm2`, `spaces`, `adjusted`; walls → `interior_walls`; openings → `openings`; diagnostics → `diagnostics`. Keys not present in `solve_json` stay absent. Parse/name errors → tool error.
