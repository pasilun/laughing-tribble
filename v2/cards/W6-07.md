Do: Implement the overlay that D40 left answering E022.

**Render** `crates/render/src/underlay.rs`: add
```rust
/// The plan drawn over the drawing: content from the plan (or `region`),
/// the underlay under it, no grid unless `grid`.
pub fn overlay(resolved: &Resolved, underlay: Underlay<'_>, opts: &RenderOptions, grid: bool)
    -> Result<Rendered, Diagnostic>;
```
It shares the SVG assembly with `scan_view`; image opacity 0.55; the plan is drawn with the ordinary plan colours so walls and openings read on the scan. Unknown `region` id keeps E011. With `grid: true` the 1 m grid and edge labels are drawn over the image.

**Server** (`crates/server/src/lib.rs`):
- `RenderArgs` gains `source: Option<String>` and `grid: Option<bool>` (default false for overlay; ignored by the other views).
- `render_value` for `RenderView::Overlay`: load the plan, pick the source (`source` name or the first), read its PNG (E024 when missing; E025 when the name is unknown; a plain tool error when the plan has no source), build `Underlay` and call `overlay`. Remove the E022 branch and the `e022` test for overlay (authorised).
- Metadata gains `source` and `calibrated`; an uncalibrated source returns I033 in the text but still draws with the nominal 1 mm/px.

**CLI** (`crates/cli/src/main.rs`):
- `plan png FILE -o OUT --view overlay [--source NAME] [--no-grid]`; assets resolve as `<plan file's dir>/sources/<plan stem>/<name>.png`, the first source by default.
- Errors print as the usual diagnostic text and exit 1. `--view` accepts `overlay`.
