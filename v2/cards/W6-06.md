Do: Hand the stored drawing back to the model as an image, so it can read printed dimensions and pick points.

**Render crate** `crates/render/src/underlay.rs` (new), `pub mod underlay;` in `lib.rs`:
```rust
pub struct Underlay<'a> {
    pub png: &'a [u8],          // the stored greyscale PNG
    pub x0: Mm, pub y0: Mm,     // plan mm of the top-left corner (the source's `at`)
    pub width_mm: Mm, pub height_mm: Mm,
}
/// Content: `region` or the whole source rect; underlay under the plan (when given)
/// and a 1 m grid with edge labels; fit to `max_tokens` like `render`.
pub fn scan_view(
    underlay: Underlay<'_>,
    region: Option<&Region>,
    max_tokens: u32,
    plan: Option<&Resolved>,
    grid: bool,
) -> Result<Rendered, Diagnostic>;
```
- Draw `<image x y width height href="data:image/png;base64,…">` first (add `base64 = "0.23"` to `plan-render`), then the grid and, when `plan` is `Some`, the same room/wall/opening elements as `View::Labels` (ids 12 px, rooms `name area`). Reuse the `pub(crate)` helpers in `svg.rs` (`drawn_elements`, `multiples`, `text`, `escape`); refactor `grid` to take the content rectangle and `mm_per_px` so both the plan SVG and this path use it. Do not change `plan_svg` output.
- Grid: every 1000 mm in plan mm; a label every 1000 mm on the top edge and the left edge (`x=…`, `y=…`, 10 px), clipped to the image.
- No new `View` variant: this is a separate path, so `render` output for `plan`/`labels` stays byte for byte the same (a test asserts it).

**Server tool** `source_view {plan_id, source?, region?: {id}|{rect_mm}, max_tokens=1600, overlay=true, grid=true}`:
1. Load the plan; pick the source by name, default the first declared. An unknown name is E025 (`Use a source name from get.`); a plan with no source is a plain tool error `The plan has no source; add one with upload.` with data `{"reason":"no_source"}`.
2. Read `<root>/sources/<plan_id>/<name>.png` (E024 when missing) and its pixel size.
3. `mm_per_px` = the source's value or 1000 (nominal); `width_mm = round(width_px * mm_per_px / 1000)`.
4. Region: `Id` → `element_rect` + 300 mm pad (E011 when unknown); `RectMm` as given; default the source rectangle.
5. `scan_view`; PNG through `plan_render::png`; return the image and metadata `{source, calibrated, mm_per_px, origin_mm, size_px, source_rect_mm, tokens, overlay}`. When `calibrated` is false, append **I033** to the text.

**Diagnostics**: add
`I033 Source "{name}" is not calibrated; give at least one printed dimension to source_calibrate.`
(info, refs `[name]`).

Tests:
- a 100×100 px PNG at `mm_per_px 10` (1000×1000 mm): default view is 1000×1000 mm, metadata `origin_mm [0,0]`, `calibrated true`;
- `region {rect_mm:[100,200,300,400]}` gives that content and origin;
- overlay with fixture A draws the plan (the SVG has room text) while `overlay:false` has no plan text;
- an uncalibrated source returns I033 and `calibrated false`;
- unknown source name → E025; unknown region id → E011;
- `plan_svg` and `render` output is unchanged (an existing snapshot test covers it).
