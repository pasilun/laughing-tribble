Files: `v2/crates/cli/src/main.rs` (or the module W1-22 put the subcommands in), `v2/crates/cli/Cargo.toml` (add `plan-render` by path if it isn't there). Parse arguments the same way W1-22 does; add no new dependency.

Behaviour:
1. `load(FILE text)`. On Err: print the diagnostics as `plan check` does, exit 1. If `resolved` is None: print the Error diagnostics as `plan check` does, exit 1.
2. Options: `--view` default `labels`; `--max-tokens` default 1600; `--region ID` → `Region::Id`; `--rect x,y,w,h` (integers, mm) → `Region::RectMm`. Both given, an unknown option, or a bad number: print `usage: plan png FILE -o OUT.png [--view plan|labels] [--max-tokens N] [--region ID | --rect x,y,w,h]` to stderr, exit 2.
3. `render` → on Err print the diagnostic message, exit 1. `png` → write the bytes to OUT.
4. Print one line of JSON to stdout: `serde_json::to_string(&viewport)`, which gives the keys in struct order: `{"origin_mm":[…],"mm_per_px":…,"size_px":[…],"tokens":…}`. Exit 0.

Tests (integration, `v2/crates/cli/tests/png.rs`, run the binary with `env!("CARGO_BIN_EXE_plan")`, write into `env!("CARGO_TARGET_TMPDIR")`):
- fixture A, default options: exit 0, the file starts with `\x89PNG`, stdout parses as JSON with `tokens <= 1600`.
- fixture A `--region Hall --max-tokens 1600`: stdout JSON is exactly `{"origin_mm":[1381,-600],"mm_per_px":2.5,"size_px":[920,926],"tokens":1122}`.
- fixture B: exit 1 (does not resolve).
- `--region Hall --rect 0,0,1,1`: exit 2.

Done when: the tests pass, and `cd v2 && cargo fmt --check && cargo clippy -q -- -D warnings && cargo test -q` is green.
